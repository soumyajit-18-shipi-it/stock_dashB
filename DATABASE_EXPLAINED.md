# Database Schema & Persistence

## Overview
The application uses **Supabase (PostgreSQL)** for long-term data persistence. The schema is designed to support user-specific data (watchlists, history) and global telemetry (predictions).

## Tables

### `users`
- **Purpose:** Extends the built-in Supabase Auth users.
- **Columns:** `id`, `email`, `created_at`.
- **Security:** Row-Level Security (RLS) ensures users can only see their own profile.

### `watchlists`
- **Purpose:** Stores tickers that users are tracking.
- **Columns:** `id`, `user_id`, `ticker`, `name`, `created_at`.
- **Relationships:** Many-to-one with `users`.

### `search_history`
- **Purpose:** Tracks recent searches for quick access and analytics.
- **Columns:** `id`, `user_id`, `ticker`, `searched_at`.
- **Optimization:** Indexed by `user_id` and `ticker`.

### `predictions`
- **Purpose:** Logs all ML predictions generated by the system for audit and performance tracking.
- **Columns:** `id`, `ticker`, `model`, `predicted_price`, `actual_price`, `confidence`, `created_at`.

### `saved_models`
- **Purpose:** Metadata for serialized `.pkl` files stored on the backend.
- **Columns:** `id`, `model_name`, `file_path`, `updated_at`.

## Security (RLS Policies)
- **Watchlists & History:** Strict isolation. Users can only `SELECT`, `INSERT`, `UPDATE`, or `DELETE` records where `user_id` matches their authenticated `auth.uid()`.
- **Predictions:** Publicly readable by authenticated users to allow for community-wide trend analysis.
